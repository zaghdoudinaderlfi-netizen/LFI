Quand les boucles
s'emboîtent

Une boucle peut en contenir une autre. C'est extrêmement utile — parcourir un tableau à deux dimensions, comparer tous les couples d'éléments — mais le coût explose vite. Ce chapitre montre comment compter ce que fait un programme avant de le lancer.

01 Boucles imbriquées

Le bloc répété par une boucle for peut contenir n'importe quelle instruction de Python — y compris une autre boucle. On parle alors de boucles imbriquées.

for i in range(3):
    for j in range(2):
        print(i, j)

La boucle extérieure est la boucle externe, celle qui est à l'intérieur la boucle interne. Pour chaque tour de la boucle externe, la boucle interne effectue tous ses tours.

✖️

Le nombre total de passages dans le corps est le produit des deux amplitudes : ici 3 × 2 = 6 affichages. C'est ce produit qui rend les boucles imbriquées coûteuses.

03 Deux exemples classiques


      
Élément commun à deux tableaux

      
Pour savoir si deux tableaux partagent au moins un élément, on compare chaque élément du premier à chaque élément du second :

      
def element_commun(t1, t2):
    for i1 in range(len(t1)):
        for i2 in range(len(t2)):
            if t1[i1] == t2[i2]:
                return True
    return False

Doublon dans un tableau — version naïve

      
Pour détecter un doublon, on compare chaque case à toutes les autres. La condition i != j évite de comparer une case avec elle-même :

      
def doublon(t):
    for i in range(len(t)):
        for j in range(len(t)):
            if i != j and t[i] == t[j]:
                return True
    return False

      
Cette version fonctionne, mais elle est doublement inefficace : chaque couple est examiné deux fois — une fois comme (i, j), une fois comme (j, i) — et la diagonale est parcourue pour rien. La section suivante corrige ce défaut.

04 Boucles imbriquées dépendantes

      
L'amplitude de la boucle interne peut être définie en fonction de la variable de la boucle externe. La boucle interne ne fait alors pas le même nombre de tours à chaque passage :

      
for i in range(1, 4):
    print("i :", i)
    for j in range(i):
        print("  | j :", j)

      

        
Python

        
        

      

      
La boucle interne tourne 1 fois, puis 2 fois, puis 3 fois : au total 1 + 2 + 3 = 6 passages, et non 3 × 3 = 9.


      
Retour au doublon — version optimisée

      
En démarrant la boucle interne à i + 1, chaque paire n'est testée qu'une seule fois, et la condition i != j devient inutile :

      
def doublon(t):
    for i in range(len(t)):
        for j in range(i + 1, len(t)):
            if t[i] == t[j]:
                return True
    return False

La version optimisée teste n(n−1)/2 couples au lieu de n²−n : exactement deux fois moins. Le gain est réel, mais l'ordre de grandeur reste le même — les deux versions restent quadratiques. Diviser par deux ne change pas la nature du problème.

    


    
    

      
05 Estimer la complexité

      
Une seule boucle peut déjà exécuter beaucoup d'instructions :

      
n = 100_000
for i in range(n):
    print(i)

      
L'effet est démultiplié par l'imbrication :

      
n = 100_000
for i in range(n):
    for j in range(n):
        print(i, j)          # 10 000 000 000 lignes

      
Et à trois niveaux, le nombre devient astronomique :

      
n = 100_000
for i in range(n):
    for j in range(n):
        for k in range(n):
            print(i, j, k)   # 10^15 lignes — inexécutable


      
Le test décisif : que se passe-t-il si on multiplie n par dix ? Le nombre de lignes est multiplié par dix dans le premier cas, par cent dans le deuxième, par mille dans le troisième. Manipule le curseur :

En informatique, la question de la performance est centrale. On s'intéresse à la complexité d'un algorithme : une estimation de la performance en fonction de la taille des données à traiter. Une estimation suffit — on cherche rarement à déterminer un temps exact.

06 Observer la complexité

      
Considérons trois fonctions qui ne font qu'incrémenter un compteur, mais dont la structure de boucles diffère :

      
def f1(n):              # une boucle
    s = 0
    for _ in range(n):
        s = s + 1
    return s

def f2(n):              # deux boucles successives
    s = 0
    for _ in range(n):
        s = s + 1
    for _ in range(n):
        s = s + 1
    return s

def f3(n):              # deux boucles imbriquees
    s = 0
    for _ in range(n):
        for _ in range(n):
            s = s + 1
    return s


      
f1 fait n incrémentations, f2 en fait 2n, et f3 en fait n². Vérifie-le :

Mesurer le temps réel

      
Le module time permet de chronométrer un bloc de code. Dans un notebook, la magic command %timeit fait la même chose en répétant la mesure plusieurs fois. Voici le schéma général — à exécuter dans Thonny ou un notebook :

      
from time import *

debut = perf_counter()
# Placer ici le code dont on souhaite mesurer le temps
fin = perf_counter()
print(f"Temps passé : {fin - debut} s")


      
# Complexite temporelle de f1
for taille in [1_000, 10_000]:
    debut = perf_counter()
    f1(taille)
    fin = perf_counter()
    print(f"Pour n = {taille}. Temps passé : {fin - debut} s")


      
⏱️
perf_counter() renvoie un instant de référence en secondes. La différence entre deux appels donne la durée écoulée. Ces mesures ne sont pas disponibles ici dans le navigateur — mais le banc d'essai ci-dessous mesure vraiment, en JavaScript, les trois mêmes fonctions.

08 L'instruction continue

      
À l'intérieur d'une boucle, continue indique qu'on ne souhaite pas exécuter la fin du tour en cours : on passe directement au tour suivant.

      
for i in range(n):
    if c:
        continue
    {bloc}

      
On obtient une boucle qui exécute {bloc} à chaque tour, sauf dans les cas particuliers où la condition c est vérifiée.


      

        

          
          
        

        
for i in range(12):
    if i % 3 == 0:
        continue          # on saute les multiples de 3
    print(i)
