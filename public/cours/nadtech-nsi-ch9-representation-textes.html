Des caractères
aux octets

Stocker ou échanger un texte revient, en informatique, à associer un numéro unique à chaque caractère. Ce chapitre explore les normes qui ont rendu ça possible — d'ASCII, limité à l'anglais, jusqu'à Unicode, qui vise toutes les langues du monde.

01 Pourquoi coder le texte ?

En théorie, représenter des caractères est simple : il suffit d'associer un numéro unique à chacun. En pratique, un bon encodage doit respecter plusieurs contraintes :

  • L'universalité : tous les ordinateurs doivent utiliser le même encodage pour pouvoir échanger des textes sans erreur.
  • La couverture : il faut pouvoir représenter un maximum de caractères, y compris des caractères non imprimables (passer à la ligne, émettre un bip) ou des commandes de protocoles de communication (accusé de réception, début de texte…).
  • La compacité : l'encodage doit économiser la mémoire et le volume des échanges réseau.
🕰️

Dans les années 50, chaque constructeur avait son propre encodage — tous incompatibles entre eux. Il fallait des programmes de conversion pour échanger le moindre texte d'une machine à l'autre. L'histoire de ce chapitre est celle d'une quête d'unification, encore en cours aujourd'hui.

02 Codage ASCII

Au début des années 60, l'ANSI (American National Standards Institute) propose une norme de codage des caractères : l'ASCII (American Standard Code for Information Interchange). Elle définit un jeu de 128 caractères, chacun représenté par un octet.

Pour trouver l'octet associé à un caractère, on concatène le chiffre de sa ligne avec celui de sa colonne dans la table ci-dessous — le résultat est un nombre hexadécimal à deux chiffres. Clique sur une case pour voir son détail :

caractère : A décimal : 65 hexadécimal : 41

Par exemple, A correspond à 41 et + à 2B.

La table ASCII regroupe plusieurs catégories de caractères :

  • les lettres majuscules (41 à 5A) et minuscules (61 à 7A) de l'alphabet latin ;
  • les chiffres 0 à 9 (30 à 39) ;
  • des signes de ponctuation, parenthèses et crochets (la virgule , vaut 2C, le crochet [ vaut 5B) ;
  • des opérateurs arithmétiques (+ vaut 2B) ;
  • des caractères spéciaux et de contrôle, non imprimables (entre 00 et 20, ainsi que 7F).

06 Bit de parité

128 caractères tiennent sur 7 bits (de 0000000 à 1111111), mais en pratique chaque caractère occupe un octet entier (8 bits). Le bit de poids fort, inutilisé par l'ASCII, sert alors de somme de contrôle pour détecter d'éventuelles erreurs de transmission.

L'idée : fixer ce bit de parité de façon à ce que le nombre total de bits à 1 dans l'octet soit toujours pair. Clique sur les 7 bits ci-dessous — le bit de parité (en rose) se recalcule automatiquement :

Octet complet = 41 (dont 1 bit de parité)

Le bit de parité vaut ici 0 — le nombre de bits à 1 dans l'octet est bien pair.

07 Normes ISO 8859

Les caractères imprimables de l'ASCII se sont vite révélés insuffisants dès qu'il fallait écrire dans une langue autre que l'anglais — même en restant sur un alphabet latin, il manque les lettres accentuées, les symboles monétaires…

L'ISO (Organisation Internationale de Normalisation) a proposé la norme ISO 8859 : une extension de l'ASCII utilisant les 8 bits de l'octet, soit 256 caractères encodables. Les 128 premiers restent ceux de l'ASCII ; les 128 suivants sont spécifiques à chaque table, notée ISO-8859-n.

La norme compte 16 tables au total, indépendantes mais compatibles entre elles. Problème : elles restent insuffisantes pour mélanger plusieurs langues dans un même texte, puisqu'un même octet peut désigner un caractère différent selon la table choisie.

08 Codage Unicode

Norme ISO-10646

Pour remplacer l'usage de pages de code multiples, l'ISO a défini un jeu universel de caractères (UCS, Universal Character Set) sous la norme ISO-10646. Chaque caractère — lettre, chiffre, idéogramme, emoji… — y reçoit un nom unique et un numéro appelé point de code.

On note un point de code U+x..x, où chaque x est un chiffre hexadécimal (au minimum 4 chiffres). Par exemple, U+006F désigne la lettre o (point de code 111). Il y a aujourd'hui plus de 110 000 caractères recensés, pour une capacité maximale théorique de 4 294 967 295 — le plus grand entier non signé sur 32 bits. Par compatibilité, les 256 premiers points de code sont ceux du latin-1 (ISO-8859-1).

Norme Unicode

Le consortium Unicode définit plusieurs techniques d'encodage des points de code, plus ou moins économiques. Ces formats de transformation universelle (UTF) portent le nom UTF-n, où n indique le nombre minimal de bits par point de code.

09 UTF-8

C'est le format le plus répandu : Linux, le Web, les protocoles réseau, Python… Il est entièrement compatible avec l'ASCII : les 127 premiers caractères sont codés sur 1 octet, exactement comme en ASCII.

Principe : si le bit de poids fort d'un octet vaut 0, c'est un caractère ASCII sur les 7 bits restants. Sinon, une séquence de bits à 1 terminée par un 0 indique le nombre d'octets utilisés ; les octets suivants commencent tous par 10 :

10 UTF-16

Ce format utilise 16 bits au minimum par caractère. Les points de code de U+0000 à U+FFFF tiennent sur un seul mot de 16 bits (2 octets). Au-delà, il faut deux mots (4 octets), appelés une paire de substituts (surrogate pair).

Encodage d'un point de code p > U+FFFF : on soustrait 10000 (hexa) à p, ce qui tient sur 20 bits ; on découpe ce résultat en deux blocs de 10 bits, puis on ajoute D800 au premier bloc (mot « haut ») et DC00 au second (mot « bas ») :

IntervalleRôle
D800 – DBFFmot « haut » (high surrogate)
DC00 – DFFFmot « bas » (low surrogate)
⚠️

Les points de code entre U+D800 et U+DFFF ne sont jamais attribués à un vrai caractère : Unicode réserve exprès cette plage aux mots de substitution UTF-16.

11 UTF-32

Ce format n'a rien d'économique : chaque caractère occupe 32 bits (4 octets), quel que soit son point de code. Son intérêt est ailleurs : puisque chaque caractère occupe le même espace en mémoire, les algorithmes de manipulation de chaînes (accès au n-ième élément, extraction d'une sous-chaîne…) sont grandement simplifiés — plus besoin de « compter » les octets pour trouver le début d'un caractère.

12 UTF et boutisme

UTF-8 est insensible à l'ordre des octets en mémoire : il se lit toujours octet par octet, dans l'ordre. En revanche, UTF-16 et UTF-32 manipulent directement des mots de plusieurs octets, et se heurtent donc au problème du boutisme (quel octet stocker en premier ?).

Pour lever l'ambiguïté, on place en début de texte le point de code U+FEFF, appelé BOM (Byte Order Mark) :

  • si les octets lus sont FE puis FF, l'ordre est gros boutien (big endian) ;
  • dans le cas contraire (FF puis FE), l'ordre est petit boutien (little endian).

Encoder et décoder

      
La méthode .encode() convertit une chaîne de caractères en une chaîne d'octets (b'...'), par défaut en UTF-8. À l'inverse, .decode() reconstitue le texte à partir des octets — à condition d'utiliser le bon encodage :

      
# longueur en caractères vs longueur en octets
s = "ßønⅉɵur"
len(s)              # 7 caractères
l = s.encode()
len(l)              # 10 octets (certains caractères prennent 2 octets en UTF-8)

# exemples d'encodage / décodage
'é'.encode()             # b'\xc3\xa9'   (UTF-8, 2 octets)
'é'.encode('latin-1')   # b'\xe9'       (1 octet)
'😃'.encode('UTF-16')   # b'\xff\xfe=\xd8\x03\xde'
b'\xC3\x85'.decode()   # 'Å'

      
🧪

Quand le décodage se trompe

      
Si un texte est décodé avec un mauvais encodage, le résultat n'a plus aucun sens — même s'il ne provoque pas forcément d'erreur. C'est une source classique de « caractères étranges » dans les pages Web ou les courriels mal configurés :

      
citation = "Der er en gammel historie..."   # texte original, en danois
information = citation.encode()                # encodage correct : UTF-8

information.decode("latin1")     # texte différent de l'original !
information.decode("iso8859_11") # texte différent, autrement

      
📌
D'où l'importance des standards : un texte doit toujours être décodé avec l'encodage qui a servi à le produire.
